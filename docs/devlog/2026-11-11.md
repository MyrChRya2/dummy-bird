### 1. 分数与成绩（ROADMAP 1.5 / 1.6 / 1.12）

- **分数＝存活时间**（用户定：「分数暂时以存活时间来计」）：`GameState.elapsed` 在 PLAYING 时每帧累加，进 READY 归零；暂停时世界整体 paused 故天然不计时。
- **时间格式＝分.秒.毫秒**（用户定：「时间以分秒毫秒计，像我设计的那个占位成绩一样」）：`format_time()` → `00.12.346`。
- **毫秒位四舍五入**（用户确认「就四舍五入吧」）：`roundf` 到整毫秒，再用整数除法按 60/1000 进制拆字段（余数由下一级接住，不丢精度）。
- **本地存档** `user://records.json`：`{best, records[]}`，最多 10 条，每条 `{score, date, reason}`。
- **排行榜界面** `scenes/ui/scoreboard.tscn`（**UI 是用户自己建的**，我接数据与入口）：
  - 开始菜单新增 **RANKING** → `GameState.State.RANKING`，`BACK` 返回
  - **行数随记录数动态增加**（用户纠正：「我只是举了三个示例，不是说排行榜就放三个」）

  - `GLOBAL` 按钮为全局榜占位（暂只记录本地）
- **设置面板新增 `RESET DATA`**：二次确认（首次变 `CONFIRM?`），清空排行榜/最高分/存档。

### 2. 障碍加速：两档线性 → 指数衰减

- 用户要求一条「单调递减、恒大于 0、过 y 轴、交点可配（默认 10）」的加速度曲线 → 对比候选后选 **指数衰减 + 半衰期**：
  ```
  a(t) = accel_start · 0.5^(t / accel_half_life)
  ```
- 关键性质：速度是加速度的积分 → **自带速度上限** `v0 + accel_start·half_life/ln2`，不需要额外限速逻辑。
- 删掉旧三参数（`speed_accel` / `accel_switch_speed` / `accel_after_switch`），`_elapsed` 从死代码变成实际在用。
- 当前值：`speed_start=120`、`accel_start=10`、`accel_half_life=20s` → 速度上限约 **408 px/s**。

### 3. 每局随机种子

- `spawner._ready()` 里 `level_seed = int(Time.get_unix_time_from_system() * 1000.0)`（进入关卡的时间戳毫秒），写进 `curve.noise_seed`。
- ⚠️ 必须先 `curve.duplicate()` 再改 —— 否则会污染共享的 `resources/ObstacleCurve.tres`。
- 实测：连续两局种子不同、`y_at(0)` 差 23.96px；共享 `.tres` 的 `noise_seed` 仍是 46190。
- 附带 `level_seed` 字段，`log_spawn` 打开时打印，便于复现某一局。

### 4. 警告清零

- `STATIC_CALLED_ON_INSTANCE`：`format_time` 从 `static func` 改为普通 `func`（Autoload 是单例实例，实例方法被 `GameState.xxx()` 调用合法）。
- `INTEGER_DIVISION`：两处单位拆分的整数除法加 `@warning_ignore` 并注明"这是语义正确的拆分，不是丢弃精度"。
- 全工程编辑器扫描 **0 条 GDScript 警告**。

### 5. 调参

- `XHoldPID`：`kd` 5 → 100、`kp` 删除（回落脚本默认 10）→ 回正系数从 0.33 降到 0.099（约慢 3.3 倍）。
- 障碍加速半衰期：10s → 20s（用户在编辑器里调）。

## 决策与理由

| 决策 | 理由（含用户原话） |
|---|---|
| **分数＝存活时间**，不是过障碍 +1 | 「分数暂时以存活时间来计」 |
| **时间格式＝分.秒.毫秒** | 「时间以分秒毫秒计，像我设计的那个占位成绩一样」 |
| **毫秒位四舍五入**（不截断） | 「就四舍五入吧」——存活时间越大越好，截断会系统性压低成绩 |
| **排行榜只做本地** | 「我大概设计了一个排行榜，暂时只记录本地，游戏记录与成绩可以储存在本地」 |
| **排行榜行数动态、5.5 行高可滚动** | 「我只是举了三个示例」／「装进一个容器里，高度大概是5行半，超出的可以拖动滚动来显示」 |
| **设置里加 RESET DATA** | 「设置里面添加一个重置游戏按钮，清空排行榜之类的本地缓存」 |
| **加速度用指数衰减 + 半衰期** | 用户要"单调递减、恒正、过轴、交点可配"；指数衰减的积分自带速度上限 |
| **每局用进入关卡的时间戳做种子** | 「将进入关卡的时间戳作为随机种子」 |
| **全局回放挂起** | 「挂起一个全局回放功能」 |

## 踩坑 / 问题

- **`git add -A` 误提交了用户未跟踪的新文件**：用户在 20:34 自建了 `score_bourd.tscn`，我提交分数系统时习惯性用 `-A` 把它带了进去。虽内容未坏，但流程错。→ 以后提交前逐条看 `git status`，用显式路径 `git add`。
- **僵尸场景三次复活**：`score_bourd.tscn` 改名后反复以未跟踪文件出现，内容仍是旧版。根因是 `GAME/.godot/editor/editor_layout.cfg` 里**还开着那个标签页**，编辑器保存时重新落盘。用户关掉标签页后确认 `editor_layout` 已干净。
- **「很多错误警告」其实是 print 刷屏**：日志里 0 条 ERROR，全是 `生成障碍物 @x=352...`（每生成一个打一行）。→ 加 `log_spawn` 开关（默认关）。
- **只查运行时日志导致误判**：我说"没有错误"，用户随后贴出编辑器里的 `W GDScript::reload` 编译期警告——那类**不在 godot.log 里**。教训：要分「运行时日志」和「编辑器调试器面板」两个来源查。
- **注释与代码矛盾**：`format_time` 注释写"截断取整、不需要四舍五入"，代码第一行却是 `roundf()`。被用户一句「为什么故意要截断取整？」问穿。→ 用户定「就四舍五入吧」，注释已更正。
