## 决策与理由

- **仓库根 = 项目根，`GAME/` 作引擎目录**
  → 文档、美术源文件、导出配置、构建脚本、发布物同仓；Godot 的 `res://` 只到 `GAME/`，文档天然不进游戏包。符合 project-management skill 的「仓库根=项目根」约定。
- **`DEV/` = 开发草稿区**（用户原话）
  → 原型阶段允许混乱，但正式资产必须有唯一规范位置；草稿验证成功再"晋升"到 `scenes/`/`scripts/`。
- **趁零引用时改名**
  → 拼写错误的目录名会长期污染检索、自动补全和肌肉记忆；Godot 里移动文件的正常姿势是编辑器拖拽（自动改引用），文件系统级改名**只在项目刚建时安全**。
- **文件树模板以「仓库内文档 + 可复制骨架」沉淀**
  → Godot 官方 Project Manager **不支持自定义项目模板**（只有 3 个渲染器预设），社区提案仍开放（[proposal #3388](https://github.com/godotengine/godot-proposals/issues/3388)、[discussion #11935](https://github.com/godotengine/godot-proposals/discussions/11935)）。因此用「复制骨架」替代官方"新建时选模板"。
- **`.gitignore` 保护 `.dsh-meow/`**
  → AI 记忆库在工作区隐藏目录里，误删不可恢复、无回收站；明确排除，防止误提交或清理。

## 踩坑 / 问题

- **⚠️ 弹窗事故：`Error: Can't run project: no main scene defined`**
  → 现象：用户在 Godot 里反复看到该警告弹窗。**根因不是我的验证命令残留进程**（已查：WSL 与 Windows 侧均无 Godot 进程），而是这个工程**从来没设过主场景**——`project.godot` 里没有 `application/run/main_scene`，所以任何"运行工程"的动作都必然触发。
  → 修复：用 `GAME/tools/set_main_scene.gd`（走引擎 `ProjectSettings.save()`，落盘格式与编辑器菜单一致）写入 `run/main_scene="uid://2or2hikoowap"`（= `scenes/playground.tscn`）。
  → 验证：`godot --headless --quit` 由 `Error: Can't run project`（exit=1）变为 **exit=0**，`no main scene` 字串出现 0 次。
  → **模板已同步堵住此坑**：骨架自带 `scenes/Main.tscn` + `project.godot` 里预置 `run/main_scene`，新项目开箱即可 F5。
- **`git mv` 用错了时机**：仓库还没初始化就把 `git mv` 当移动命令用 → 报 `source directory is empty`。**教训：未跟踪的文件用 `mv`，已跟踪的才用 `git mv`。**
- **目录撞名导致脚本中断**：`mkdir assets/scenes` 与后来的 `mkdir scenes` 混淆，`set -e` 下中断，只完成了一半。**教训：批量目录操作先 `find` 看一遍现状再动手，或每步后验证结果。**
- **DrvFs 不写 NTFS 可执行位**：`chmod +x` 在 `/mnt/d` 上不生效，git 里存成 `100644`，换机 clone 后 `./new-game.sh` 会 Permission denied。**修复：`git update-index --chmod=+x`。**
- **Windows Godot 不认 WSL 路径**：`--path /tmp/...` 报 `Invalid project path`。**修复：`wslpath -w` 转成 Windows 路径。**（且 `/tmp` 不在 Windows 可见范围，测试要放 `/mnt/d` 下）
- **`--headless --quit` 会退出而不是等编辑器**：想触发文件系统扫描要用 `--editor --quit-after N`。
- **不要手写场景文件的 UID**：Godot 的 UID 是 `0-9a-v` 编码，随手编的 `uid://...` 可能非法。**正确做法：只写路径，让引擎自己生成 UID。**

### 关于「能不能全部 CC0」的结论（备查）

用户最初想用 CC0，经核实后**改用 MIT**，理由三条：

1. **CC0 明文排除专利授权**——其授权只覆盖版权及相关权利，明确声明专利与商标不在其中。软件仓库最需要的恰是显式的专利授予，这是 MIT/Apache-2.0 的立意所在。
2. **两仓当时没有任何原创美术**：`SOURCE/` 为空，全仓唯一图形文件 `GAME/icon.svg` 经核实是 **Godot 官方默认工程图标**（第三方内容，用户无权给它换许可）。CC0 擅长的"素材/数据"场景并不存在。
3. **法律确定性更差**：CC0 为"放弃权利"而设计，下游（公司、包管理器、法务）反而难以判断获得了什么。MIT 同样达成"最大程度开放"（允许闭源商用/修改/再分发）。

将来若给美术素材单独授权（`SOURCE/` + `assets/` 用 CC0 而代码保持 MIT），已在 `PROJECT_INDEX.md` 第八节登记该约定。

### 本轮的关键发现（都做了实测，不是推断）

**① 像素渲染地基缺失（P1）——已用引擎实测确认方案**

做了一个对照实验：造两个最小工程，A 不设置、B 设置 `[rendering] textures/canvas_textures/default_texture_filter=0`，用探针脚本读引擎实际值：

| 工程 | `ProjectSettings.get_setting(...)` 读到的值 |
|---|---|
| A（未设置） | **1 = Linear**（引擎默认） |
| B（`=0`） | **0 = Nearest** ✅ |

→ **键名与取值双重确认**。而真实工程 dummy-bird 实测读到的是 **1（Linear）**——即当前像素画会被线性过滤**糊掉**。这从"我的建议"升级为"已验证待执行"。

**② 视口尺寸是引擎默认的 1152×648**

实测 `display/window/size/viewport_width/height` = 1152×648。像素风需要的是一块**小的逻辑画布**（如 320×180 / 640×360），这块也要在素材开画前定。

**③ 文档失真一处，当场修正**

`GDD.md` §5.1 原本写着 `config/features = 4.7, Forward Plus`，而实际已随渲染器切换变为 `GL Compatibility`——**文档落后于代码**。已修正。
（另修正 `ROADMAP.md` 0.4 里指向已删除的 `templates/godot-2d/` 路径。）

**④ itch.io 的 Web 导出必须单线程**

itch.io 不发送 COOP/COEP 响应头，而 Godot 的多线程 Web 导出依赖 `SharedArrayBuffer`——面向 itch.io 托管时必须**关闭线程支持**，否则加载失败。已在 `GDD.md` §5.3 P4 与决策记录中登记。

### 本轮的验证过程（含一次自我纠错）

**① 枚举取值：先踩坑、再让引擎给出权威答案**

我最初写了个断言，用 `CanvasItem.TEXTURE_FILTER_NEAREST` 去比对项目设置里读到的值，结果报"不匹配"。
**但这个断言本身是错的**——`CanvasItem` 的枚举是 `0=PARENT_NODE, 1=NEAREST, 2=LINEAR`，而 ProjectSettings 用的是**另一套**枚举。

于是改用 `ProjectSettings.get_property_list()` 让引擎自己报定义：

```
hint_string = "Nearest,Linear,Linear Mipmap,Nearest Mipmap"
默认值 = 1
```

→ **0 = Nearest，1 = Linear（默认），2 = Linear Mipmap，3 = Nearest Mipmap**。我们的设置 `0` **是正确的**。

**教训**：验证一个枚举值时，必须用**它的定义方**给出的枚举，不能拿同名但不同域的另一套常量来比对——否则会得到"设置错了"的假警报，进而做出错误的"修复"。这个坑已写进工具脚本头部注释。

**② `--headless` 下窗口尺寸是 (0,0)，比例量不出来**

我本想通过读视口与窗口的比例来判断缩放行为，但无头模式下 `DisplayServer.window_get_size()` 返回 `(0,0)`，所以**比例没法测**。如实记录：这个测法有缺陷，未得出比例结论。

不过探针确认了一条有价值的事实：**`expand` 会按需扩展视口短轴**（800×450 窗口 → 视口 320×**320**），这正是"不会产生黑边"的机制——横屏多机型适配的关键。

### 查出一处我先前写错的地方（重要）

`.gitignore` 里我写了 `export_presets.cfg` 被忽略 —— **这是错的**。Godot 官方的[版本控制系统文档](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html)建议**提交**该文件：它记录 Web/Android 的导出配置（选项、包名、图标），正是"M3 双端导出"要依赖的东西；忽略它等于每次换机都要重新配一遍。

因此修正为：

| 规则 | 处理 |
|---|---|
| `export_presets.cfg` | **改为提交** |
| `EXPORTS/` `build/` `dist/` | 仍忽略（只忽略产物） |
| `*.keystore` `*.jks` `*.pepk` | **新增忽略**（签名密钥绝不入库） |
| `*.uid` | **明确有意不忽略**（Godot 4.4+ 稳定资源标识，官方建议提交；否则引擎按路径重建 UID，改路径时易引用错乱） |

**同一个错误也存在于独立模板仓**（`godot-2d/.gitignore` 与 `new-game.sh` 内嵌的仓库级 .gitignore）——不修的话每个新项目都会继承这个坑。已同步修正并做了端到端验证：生成新项目后 `export_presets.cfg` 可提交、`release.keystore` 被忽略。

### 学到的一个关键点

只调 `InputMap.add_action()` **不会写回** `project.godot`——那只在运行时生效。必须同时写 `ProjectSettings` 的 `input/<动作名>` 再 `save()`。这个坑已写进工具脚本注释。
