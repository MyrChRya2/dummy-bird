## 今日摘要

给玩法补了三层"手感/流程"：**开局准备阶段**（READY：一切冻结，玩家首次点击才开始）、**障碍速度两档线性加速**（从 120 起、到 400 后换更快一档），以及小鸟被撞后**挣扎回正**的横向 PID 控制器。中途查清并修掉了 PID 的高频震荡（一帧滞后导致的周期-2 发散），顺手修了调试面板 F1 失效。

## 完成内容

- **开局准备（READY）**：`GameState` 增 `READY` 状态 + `begin_play()`（幂等）；开始菜单 START → READY；`main.gd` 拦截首次 `flap` → PLAYING；重开也走 READY；HUD 加 `ReadyHint`（"TAP TO START"，仅 READY 显示）。世界在 READY 已经装载但**整体暂停**，所以鸟静止、障碍不生成、曲线不动。实测：READY 停 1.5s，鸟位移 0.00px、障碍 0 个；首次点击后立即解冻并开始生成。
- **障碍速度两档线性加速**：`spawner.gd` 新增 `speed_start` / `accel_switch_speed`(=400) / `accel_after_switch`；`speed` 改为只读的当前值，用 **逐帧积分** `speed += current_accel()·delta`（不是 `v0+a·t`，否则换档时速度会跳变）；`speed_start` 带 setter，改它会把当前速度立刻重置，方便现场试。实测：1 秒 +1 的线性段正确；跨过 400 后从 10 平滑换到 5。
- **小鸟横向回正 PID（`XHoldPID`）**：新组件节点挂在 `Player` 下（**没改 Player.gd**），输出 `velocity.x` 交给已有的 `move_and_slide()`；参数分三组——PID（`kp`/`ki`/`kd`）、**限速与限加速度两个开关**（`use_max_speed`/`max_speed`、`use_max_accel`/`max_accel`）、其它（`integral_limit`/`deadband`）。被撞后速度是负值，控制器从这个负速度开始刹车、再爬回 120。
- **调试竖线**：`tools/debug/target_x_line.gd` + `playground` 根节点下的 `TargetXLine`，在 x=120 画一根淡红虚线，方便观察回正效果。
- **修复**：①F1 调参面板完全没反应；②PID 在目标点附近高频震荡、偶尔瞬移。

## 决策与理由

- **READY 用"整体暂停"实现**，而不是给 spawner/Player 各加一个 `started` 开关 → 一处机制同时冻结角色、生成器、曲线预览，**以后新增的系统也自动被冻住**，不会漏。
- **速度改成逐帧积分**（`v += a·dt`）而不是解析式 `v = v0 + a·t` → 换档瞬间速度连续，只有斜率变。
- **PID 的阻尼项在帧内解出**：`v = (kp·e + ki·∫e) / (1 + kd)`，而不是用误差帧间差分 → 消除一帧滞后带来的发散（详见下面踩坑）。
- **每个"额外行为"都给开关**（`use_max_speed` / `use_max_accel`）→ 用户要能一键关掉做 A/B 对比。
- **放弃"撞击冲量"和"被推时速度跟随障碍物"两版实现** → 用户明确要的是"被推时速度是负的、从负值开始回正"，试过两版后决定回退到纯 PID（保留 `max_accel` 开关来消弹射感）。
- **收尾问答后的定论（2026-11-06，用户逐条回复）**：
  1. **撞到障碍物不致死** —— 用户原话「障碍物运动速度很快，撞击直接死亡太苛刻」，**死亡判定改为「掉出屏幕 / 被推出屏幕」**；撞障碍只被推退（横向回正机制**保留**）。另**挂起一个「死亡特效」任务**。
  2. 速度曲线「目前我玩着体感还行，可能需要其他玩家去反馈」→ 暂按当前值当起步值，不改。
  3. PID 参数「我玩着 OK，需要收集反馈再调整」→ 同上，暂定。
  4. **调试件不再"发布前整体删除"** —— 「调试相关的功能当然不能留着发布，计划**解耦出来合并到我的 F3-debugger** 里面」：功能要保留复用，只是不能进正式包。

## 踩坑 / 问题

- **PID 周期-2 发散（今天最花时间的一个）**：D 项用误差帧间差分，等价于 `v_n = kp·e_n − kd·v_{n−1}`——**读的是上一帧速度（一帧滞后）**。特征方程 `λ² − (1−kp·Δt−kd)λ − kd = 0`，kd=1 时有一根 ≈ **−1.09**（|λ|>1 且为负）、kd=3 时 ≈ −3.1 → 目标附近**一帧左一帧右、幅度越来越大**。视觉上就是"一只小鸟裂成两只"，关掉 `max_speed` 后发散不被截断，甚至飙到 8 万 px/s、瞬移几百像素。诊断手法：数后半段 `velocity` 的**符号翻转次数**（修好后为 0）。
- **F1 调参面板没反应**：①`playground.tscn` 里那个 `CanvasLayer` 被存成了 `visible = false`，而脚本切的是内部 `_panel.visible` → 怎么切都看不见；②世界是 `PROCESS_MODE_PAUSABLE`，READY/暂停时 `_input`/`_process` 都不跑。修法：脚本强制 `visible = true` + `process_mode = PROCESS_MODE_ALWAYS`，面板默认收起。
- **检查器里改的值没生效**：`Speed Start` 调到 120 但场景文件里没存 `speed_start`（只存了 `speed_accel`）→ 回落到脚本默认 100。`@export` 值有**三层来源**（脚本默认 → 场景覆盖 → 运行时改），**只有保存场景才持久**；排查手段是直接 `grep 属性名 场景文件`。
- **headless 探针的两个坑**：探针节点必须自己设 `PROCESS_MODE_ALWAYS`（否则 MENU/READY 时暂停，表现为"只打印了 `_ready` 那行就没下文"）；用 `timeout` 杀 headless Godot 会丢 stdout 缓冲（表现为"完全没输出"）→ 用 `--quit-after` 或让探针自己 `quit()`。
