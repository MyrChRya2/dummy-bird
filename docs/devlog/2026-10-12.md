## 决策与理由

见 `docs/ROADMAP.md` §3 的 2026-10-12 六条，摘要：
1. **世界按需装载/卸载** → 主菜单不跑不占；RESTART＝卸载重建，省掉手写"世界重置"。
2. **SETTINGS 做成叠加状态 + 浮层** → `_world_wanted` 把世界存亡与状态解耦，从暂停进设置不会弄丢暂停画面；音量/全屏属 M2（用户明确先不着急）。
3. **不单独建 `SceneDirector`** → 装配并入 `main.gd`，避免状态映射散在两个单例。
4. **输入方案**：`flap` 去掉空格（用户要求）；跳跃改 `_unhandled_input` 事件驱动。
5. **失败信号"一条出口、多种触发源"**：`report_failure(reason)` 幂等，检测方只报告。
6. **平台差异**：Web/移动端不提供"退出游戏"（仅桌面），但"返回主菜单"三端都要。

## 踩坑 / 问题

- **InputMap 动作是全局状态**：`flap` 绑鼠标左键时，点任何 UI 按钮都会顺带触发一次跳跃（`Input.is_action_just_pressed` 不看 GUI 是否消费）。改 `_unhandled_input` 后解决——实测 A/B：点空白处 `velocity.y=-18.3`（跳了）、点暂停按钮 `velocity.y=24.5`（没跳）且状态变 PAUSED。
- **`PROCESS_MODE_ALWAYS` 会向下传染**：给 `Main` 设 ALWAYS（为了暂停时还能收 Esc）后，整棵游戏树跟着无视暂停——`paused=true` 但玩家照掉、障碍照生成。修法：世界显式设 `PROCESS_MODE_PAUSABLE`。
- **编辑器保存会覆盖外部改动**：在编辑器外改了 `pause_menu.tscn` 的按钮名，用户随后在编辑器保存，改动被整体回退。（改完必须让对方 Reload Saved Scene。）
- **静态警告不进日志**：`INCOMPATIBLE_TERNARY` 只出现在编辑器 Debugger 面板；`--check-only` / `--editor --quit` 都不打印（实测故意写坏也不报）→ 只能按定义改 + grep 同类模式排查。
- **僵尸场景会复发**：`DEV/test_scenes/{obstacle,obstacle_half,test_scence}.tscn` 清过一次又出现（引用的旧路径全不存在、引擎扫描报 `File not found`），本次再清（零引用确认）。
