## 0. 项目目的（决定取舍的最高优先级）

> 用户原话（2026-10-11）：**「这个项目主要目的是学习技术美术。」**

**dummy-bird 的完整定位 = 以一款 2D 像素点击跳跃小游戏为载体，学习技术美术（技美）。**
游戏本身是**载体 / 练兵场**，技美能力（shader、特效、渲染、动画）才是主要产出。

### 0.1 这条目的如何影响决策

当出现取舍时，**优先选"能学到东西"的方案**，而不是"最省事"或"最像成品"的方案：

| 场景 | 按"做成品"会怎么选 | 按"学技美"应该怎么选 |
|---|---|---|
| 加一个效果 | 用现成插件/内置节点拼出来 | **自己写 shader 实现一遍**，理解原理 |
| 美术方案 | 用现成素材包 | **自己做一层**，练手绘/导出/规格控制 |
| 卡住了 | 绕过去，先让游戏能跑 | **停下来搞懂**，因为搞懂本身就是目的 |
| 发布 | 尽快上架 | 上架是**检验手段**，不是终点 |

### 0.2 推进顺序（用户指定）

> 用户原话（2026-10-11）：**「明天尝试做一套UI框架，主要是开始菜单、暂停界面。先把游戏的整套框架搭建起来然后研究技美。」**

```
① 整套框架（UI 框架：开始菜单 / 暂停界面 / 状态流转）  ← 当前
        ↓
② 研究技美（shader / 特效 / 渲染 / 动画）
        ↓
③ 发布（itch.io + TapTap）—— 作为检验手段
```

**对项目管理的含义**：技美实验是**一等公民**，值得占据独立里程碑，不能推到"最后打磨"阶段；
发布目标保留，但重要性低于学习收益。

## 1. 一句话概述

> **一次点击 = 一次跳跃的 2D 像素街机游戏**：玩家控制一只不断坠落的鸟，靠点击/按键维持飞行高度，穿过不断出现的障碍，比谁活得久。
> 无剧情、无叙事负担——纯粹的手感与反应挑战，单局时长以秒计，失败后必须立刻想再来一次。

| 项 | 内容 |
|---|---|
| 项目名 | **DummyBird** |
| 类型 | 2D 像素 · 点击跳跃（one-tap）· 街机 / 无尽跑酷 |
| 玩法参照 | 「笨鸟先飞」式点击跳跃（Flappy Bird 一类的单键操作设计） |
| 操作核心 | **单键**：点击 / 空格（桌面）＝ 屏幕任意处轻触（移动端） |
| 剧情 | **无**（定位明确） |
| 目标平台 | **网页端 → itch.io** ｜ **移动端 → TapTap** |
| 商业模式 | ⬜ 待定（免费 / 广告 / 买断） |
| 单局时长 | ⬜ 待定（参考量级：10 秒～2 分钟） |

## 2. 核心玩法循环（Core Loop）

```
        点击/轻触（唯一输入）
              ↓
        鸟获得一次向上冲量（瞬时速度）
              ↓
     重力持续下拉 → 形成"抬手就掉"的节奏
              ↓
   穿越障碍缝隙 ──成功──→ 分数 +1 → 回到"点击"
        │
        └──失败──→ 碰撞判定 → 结算 →【立刻重开】：一局结束到下一局 ≤ 1 秒
```

- **10 秒内重复的动作**：观察高度 → 决定点或不点 → 点。**决策密度高、间隔极短**，这是全部乐趣来源。
- **失败**：撞到障碍或掉出屏幕 → 立即结算。
- **奖励**：分数递增 + 手感上的"连续通过"爽感。分数是唯一进度载体（无剧情、无养成）。

### 2.1 待定的核心循环参数

| 项 | 说明 | 状态 |
|---|---|---|
| 障碍形态 | 上下管道 / 间隙墙壁 / 移动障碍——越简单越贴合单键手感品类 | ⬜ |
| 难度曲线 | 恒定速度 / 逐步加速 / 间隙变窄 | ⬜ |
| 分数规则 | 每过一个障碍 +1 / 距离计分 | ⬜ |
| 最高分持久化 | 本地存档（`user://` 或 Web 端 localStorage） | ⬜ |
| 是否加道具/变体 | 建议**先不加**——先把单键手感做对 | ⬜ |

## 3. 操作与手感

### 3.1 输入映射（已定）

| 平台 | 输入 | 备注 |
|---|---|---|
| 桌面网页（itch.io） | **鼠标左键点击** 或 **空格键** | 两种都要支持，网页玩家习惯不一 |
| 移动端（TapTap/Android） | **屏幕任意处轻触** | 单指可玩，无需虚拟按键 |
| 统一实现 | ✅ **已落实**：Godot `Input Map` 的 `flap` 动作绑定上述全部输入 | 只写一份判定逻辑；在代码里用 `Input.is_action_just_pressed("flap")` |

### 3.2 手感参数（待调，但必须"外露"）

手感是这个品类的全部，因此**所有关键参数都要集中在同一个脚本/资源里可调**，不要散落在场景节点上：

| 参数 | 含义 | 起步值 |
|---|---|---|
| `jump_velocity` | 每次点击的瞬时上升速度 | ⬜ 靠试 |
| `gravity` | 重力加速度 | ⬜ 靠试 |
| `max_fall_speed` | 下落速度上限（防坠太快没法救） | ⬜ 靠试 |
| `scroll_speed` | 障碍/背景推进速度 | ⬜ 靠试 |
| 输入缓冲 | 提前点是否记录（提升容错） | ⬜ 建议做，提升明显 |

> **调参纪律**：改一个参数 → 立刻试玩 → 记录感受。手感靠试不靠算——写进 devlog，避免反复推翻。

### 3.2b 工程约定：自定义节点图标

作者用 `@icon()` 注解给脚本挂了自定义图标，方便在编辑器里一眼分辨节点类型（`state.svg` 用于状态机脚本）。

| 约定 | 说明 |
|---|---|
| 注解位置 | `@icon("res://...")` **必须在脚本最顶部**，放在 `extends` / `class_name` **之前**，否则报 `Annotation "@icon" must be at the top of the script` |
| 写法 | 是**注解**不是语句——写成裸的 `Icon "..."` 会报 `Parse Error: Unexpected identifier "Icon" in class body` |
| 显示前提 | 脚本需要有 `class_name`，否则编辑器里图标不显示 |
| 图标文件位置 | 当前 `GAME/scripts/state.svg`（**刻意与脚本同目录**）。⚠️ 它被 `res://` 引用，**移动必须在编辑器里做**或同步改 `@icon` 路径 |

### 3.3 移动端特有约束（由 TapTap 定位推导）

- **轻触全屏**可能与系统手势冲突（返回手势/通知下拉），需实测是否需要留边距。
- **没有键盘暂停**：移动端要单独考虑暂停入口；切后台应自动暂停 + 静音。
- **横屏已定**（2026-10-11）：参照「滑雪大冒险」的横屏侧视形态。横屏意味着**双手握持**，单键输入仍要保证"任何姿势都能点到"——因此触控区域取全屏、不分左右，但要注意左右拇指的落点都在有效区内。

### 5.3 由「网页 itch.io + 移动 TapTap」推导的工程前置

> 这几项**必须在动手做玩法之前确认**。尤其像素渲染设置——素材一旦按错误设置画好，全部要重做。

| # | 项 | 说明 | 状态 |
|---|---|---|---|
| **P1** | **像素完美渲染** | ✅ **已完成**。`textures/canvas_textures/default_texture_filter=0`（**0 = Nearest**）。枚举权威定义由引擎给出：`hint_string = "Nearest,Linear,Linear Mipmap,Nearest Mipmap"`、默认 1 → 0=Nearest,1=Linear,2=Linear Mipmap,3=Nearest Mipmap。<br>⚠️ 易踩坑：`CanvasItem.TEXTURE_FILTER_*` 是**另一套**枚举（0=PARENT_NODE,1=NEAREST,2=LINEAR），两者不能混用比对。工具：`GAME/tools/engine/set_pixel_perfect.gd` | ✅ 2026-10-11 |
| **P2** | **窗口拉伸方式** | ✅ **已完成**：`canvas_items` + `expand` + `integer`。选型依据（实测）：`expand` 会按需扩展视口短轴（800×450 窗口下视口变 320×**320**），因此**不会产生黑边**，适合横屏多机型；`integer` 保证整数倍缩放、像素均匀。若某机型出现黑边或抖动，把 `scale_mode` 改回 `fractional`、或换 `viewport` 模式即可（两者都是单行改动） | ✅ 2026-10-11 |
| **P3** | **屏幕方向与窗口尺寸** | ✅ **已完成**：**横屏** + 基础视口 **320×180**（16:9，1080p 的整数倍）。`handheld/orientation=1` | ✅ 2026-10-11 |
| **P4** | **Web 导出预设** | 目标 itch.io。⚠️ **itch.io 托管需用「单线程」Web 导出**——itch.io 不发送 COOP/COEP 响应头，而 Godot 的多线程 Web 导出依赖 `SharedArrayBuffer`，会加载失败；官方文档明确建议面向 itch.io 时关闭线程支持。横屏 16:9 在网页里也更贴合常规显示比例 | ⬜ 待配置 |
| **P5** | **Android 导出预设** | 目标 TapTap。需 Android SDK + JDK + 签名密钥库。**可不必本地装**：本机已有 GitHub Actions CI 基础设施，可用它构建 APK | ⬜ 待配置 |
| **P6** | **触屏与系统手势** | 全屏轻触可能撞上返回手势；切后台需自动暂停（见 §3.3） | ⬜ |
| **P7** | **设置项外露** | 音量、音效开关——移动端玩家预期要求有；建议 M2 前留好入口 | ⬜ |

> 导出模板状态（实测）：本机已装 Godot **4.7.1** 与 4.6.3 的导出模板，P4/P5 缺的不是模板，而是导出预设与签名配置。

### 5.4 框架架构（2026-10-11 用户确认三项选型）

> 推进顺序见 §0.2：**先搭整套框架（UI：开始菜单 / 暂停），再研究技美**。
> 本节是**架构方案**（决策与理由），玩法实现由作者自己写。

三项已定选型：

| # | 选型 | 结论 | 理由 |
|---|---|---|---|
| 1 | 框架分层 | **全局状态机 + 场景管理器（Autoload 单例）** | 任何地方都能读取游戏状态；**技美做全屏特效时也需要读状态**（如暂停时压暗、命中时闪白） |
| 2 | UI 挂载 | **单主场景：`World` + `UILayer` 并列** | 暂停时**只暂停 World，UI 仍响应**——这是 Godot 里暂停系统最稳的做法 |
| 3 | UI 字体 | **先用内置默认字体** | 像素字体在缩放/字号上很敏感，属于技美/美术环节，放到②阶段专门调 |

#### 5.4.1 场景树形状（方案）

```
Main.tscn                        ← 新的主场景（当前主场景是 playground.tscn）
├── World          (Node2D)      # 游戏层：关卡/角色/障碍挂在这里
└── UILayer        (CanvasLayer) # UI 层：菜单/暂停/HUD，永远在 World 之上
```

**为什么用单主场景而不是"每个界面一个场景直接切"**：暂停需要"游戏画面保持在屏幕上、只是停住"，
用 `change_scene_to_file` 换场景会把游戏画面丢掉。`World` + `UILayer` 并列，
暂停时对 `World` 设 `process_mode = PROCESS_MODE_DISABLED`（或 `get_tree().paused = true`）即可。

#### 5.4.2 状态机（方案）

```
GameState:  MENU  →  PLAYING  →  PAUSED  →  GAME_OVER
                       ↑            │
                       └────────────┘（恢复）
```

- **状态机管"当前处于哪个状态"**，不管"怎么画 UI"——UI 监听状态变化并显隐自己。
- 建议用 **Autoload 单例**（如 `GameState`、`SceneDirector`），因为状态要跨场景存活。
- ⚠️ **注意**：Autoload 是全局的，**调试件不要往 Autoload 里塞**（发布时要能整体删掉 `tools/debug/`）。

#### 5.4.3 暂停语义（容易踩的细节）

| 项 | 约定 |
|---|---|
| 暂停实现 | 优先 `get_tree().paused = true` + 让 UI 节点设 `process_mode = WHEN_PAUSED`（或 `ALWAYS`） |
| 恢复 | 必须**复位到暂停前的状态**（`PAUSED → PLAYING`，不是硬编码回 PLAYING） |
| 切后台 | 移动端切后台应**自动暂停 + 静音**（见 §3.3） |
| 音频 | 暂停时 BGM 是否继续？⬜ 待定（建议：继续播低音量，或暂停——需试听决定） |
| 计时 | ⚠️ 若以后要计"本局用时"，暂停时**必须停表**（用 `delta` 累积即可自动满足） |
